Three separate facts — never mergedregional quota ≠ zonal access
vCPU quota — regional
Subscription × region × family. There is no per-zone vCPU quota; AQR never splits it into zones.
SKU access — zonal
Subscription × region × SKU × zone: offered (locationInfo.zones) and not restricted (restrictions[type=Zone]).
Zone identity — per subscription
Logical zone "1" can be a different datacenter in each subscription. Cross-sub views use physical zones.
🔐  Identity — no secrets
One UAMI: Reader on management groups, contained SQL database user (Entra-only, no SQL logins), Storage Blob Data Contributor. Shared keys disabled. No Key Vault needed in v1.
🛡  Network Security Perimeter
SQL server + storage associated. SQL NSP is public preview (storage GA); AQR_SQL_NETWORK=privateEndpoint is the GA alternative. Inbound: managed identities from the AQR subscription.
🚀  azd up
Bicep provisions RG, App Service, UAMI, Azure SQL, storage, NSP (or VNet + private endpoints), App Insights, Entra app. Hooks check az context, create the DB user, print MG RBAC if needed.
Observability: SyncWorker emits snapshot age, subscriptions covered vs expected, rows written and throttling to Application Insights. A stage covering less than 100% of subscriptions is a warning on the Admin page, never a silent success.
